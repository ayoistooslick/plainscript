Regular expressions

Regular expressions are values in PlainScript. A literal is parsed by the lexer, assigned the primitive type regex, and compiled to a native JavaScript RegExp. The pattern engine is therefore the host's engine: V8 in Node and in Chromium, with the same capture, lookaround, Unicode and replacement semantics as the JavaScript running beside it.

PlainScript adds a type, a literal syntax and compiler diagnostics. It does not wrap matches in a second engine.

Literals

A literal has the form /pattern/flags. The parser records both parts:

  • pattern is the text between the slashes, with backslashes preserved.
  • flags is the suffix drawn from d, g, i, m, s, u, v and y.

    • Flags are validated by the host engine, so an unsupported or duplicated flag is a compile-time error rather than a runtime surprise.

  • Empty patterns (//) are legal; they match at every position.

Slash versus division

The lexer decides by expression position. A / after a value is division; a / where an expression is expected starts a regex:

After identifiers, literals, calls, member access, closing brackets and nothing, / is division. After operators, commas, opening brackets, return and similar expression starts, it begins a regex. Write width / 2 with spaces if a pattern is ever visually ambiguous; escaping a slash inside the pattern as \/ is always valid.

A regex is JSON-serialisable as {} like a JavaScript RegExp; do not send it across a process boundary expecting pattern text. Send source and flags and reconstruct on the other side.

Because test delegates to the native object, a global or sticky regex keeps lastIndex between calls. Use a fresh literal for a stateless test, or use the std/text helpers, which reset the index for each call.

Matching and captures

std/text provides typed helpers that return records rather than native match arrays. They are usually clearer than unpacking JavaScript's array shape.

RegexMatch is a record:

  • groups[0] is the first positional capture, matching JavaScript's

    • match[1] convention. text is the full match.

  • named contains named captures by group name.
  • A participating empty group is "". A group that did not participate is also

    • an empty string, because the record stores text rather than nullable slots.

  • findMatch returns nothing when there is no match.
  • findAllMatches and matchTexts reset lastIndex, so a global literal is

    • safe to reuse.

Replacement and splitting

Replacement strings use JavaScript's native substitution syntax: $& for the whole match, $1 for a capture and $<name> for a named capture. replaceMatch replaces the first match; replaceAllMatches replaces every match and adds the g behaviour itself. splitMatch splits on every match and returns a list of text.

escapeRegex escapes the characters that have special meaning in a pattern. It is for building a literal from user text, not for turning arbitrary input into a trusted pattern.

Unicode, multiline and zero-length matches

The flags are the host's:

  • u enables Unicode code-point matching; v enables the Unicode sets mode in

    • engines that support it.

  • m makes ^ and $ match at line boundaries.
  • s makes . match newlines.
  • i uses Unicode-aware case folding when combined with u.
  • g and y are stateful on the native RegExp; the std/text helpers reset

    • the index.

Zero-length patterns are valid. A global zero-length match advances by one position in JavaScript, and PlainScript inherits that behaviour:

Diagnostics

CodeMeaning
PS1006Unterminated regex literal

Pattern validation runs when the literal is lexed. The diagnostic includes the engine's reason, for example Unterminated group or Invalid group, so a bad pattern fails plainscript check before any module executes.

Differences from JavaScript

  • There is no RegExp constructor in the language surface. Use a literal, or

    • call a declared host API if a truly dynamic pattern is required. Dynamic patterns cannot receive compile-time validation.

  • A regex is typed regex, not object or any. This is a PlainScript

    • addition; the emitted value is a native RegExp.

  • The checker rejects reading native array-shaped match properties directly

    • from a regex; use std/text helpers for captures.

  • The pattern language is exactly the host's. PlainScript does not claim

    • cross-engine portability for features one engine lacks.

Runtime compatibility

The emitted code uses a JavaScript regex literal, so it runs in Node and every browser that V8 or another supported engine runs. There is no regex polyfill and no runtime dependency. Replacement and split helpers live in std/text and are plain JavaScript functions.
