PlainScript 2.1

PlainScript is an independent, statically typed programming language for the JavaScript platform. It reads like structured English, checks every program before it runs, and compiles to ordinary ES modules that use the JavaScript ecosystem directly — React, Next.js, Vite, Express, Node built-ins and npm packages included.

Version 2.1 introduces the English-oriented dialect as the primary surface of the language. It is opt-in per file, so 2.0 sources keep compiling unchanged.

Created by Ayodele Ayokunle David. PlainScript is MIT licensed.

---

Quick start

PlainScript needs Node.js 20 or newer and has no runtime dependencies.

#syntax 2.1

# hello.pln
import { print } from "std/io"

define greet(name: text) returns text
    return "Hello, {name}!"
end

print(greet("world"))
node src/cli.js run hello.pln
# Hello, world!

Check types without running, or compile a project to ES modules:

node src/cli.js check hello.pln     # type-check only
node src/cli.js build               # compile src/**.pln into dist/
node src/cli.js new my-app          # scaffold a project
node src/cli.js fmt                 # normalise formatting

Once installed as a package the same commands are available as plainscript.

Why the syntax looks different

PlainScript is not JavaScript with renamed keywords. It has one spelling per concept, blocks that close with end, and a checker that enforces the language before anything runs.

2.1 chooses words for how a declaration reads aloud:

Concept2.02.1
Immutable bindingconst total = 0value total is 0
Mutable bindinglet count = 0set count to 0
Assignmentcount = count + 1change count to count + 1
Functionfunction greet(name: text) -> textdefine greet(name: text) returns text
Conditionif / else if / elsewhen / otherwise when / otherwise
Each loopfor item in itemsfor each item in items
Range loopfor i in 0 to 9for i from 0 to 9
Comparisona >= ba is at least b

Two rules keep the dialect coherent rather than a second set of aliases:

  1. A 2.1 file has one spelling per concept. Writing let or function

    2. inside a #syntax 2.1 file is a compile error with the 2.1 word as a hint.

  2. Only words that read better were changed. match, case, try,

    3. catch, finally, while, import, export, async, await, and, or, not and render are already English and keep their spelling.

value, set, change, define, returns and each are contextual: they introduce a construct only where that construct can appear, so they remain usable as ordinary identifiers — value can still be a parameter name, and for each in names binds a loop variable named each.

2.0 is not deprecated. A file without a pragma compiles exactly as it did before, and 2.0 and 2.1 modules can import one another in the same graph. See the migration guide.

A project can standardise on 2.1 without a pragma in every file, and still keep exceptions:

{
  "compilerOptions": {
    "rootDir": "src",
    "outDir": "dist",
    "syntax": "2.1"
  }
}

A #syntax 2.0 pragma in an individual file overrides the project default, and plainscript --syntax=2.1 <command> overrides both for a single run. Precedence is: file pragma, then --syntax, then plainscript.config.json, then 2.0.

A short tour

#syntax 2.1

import { print } from "std/io"
import { filter, map, sum } from "std/list"

# Records are structural types.
type Person
    name: text
    age: number
end

# Variants are discriminated unions; unit variants are plain strings.
type Shape = Circle(radius: number) or Rectangle(width: number, height: number) or Point

define area(shape: Shape) returns number
    match shape
    case Circle(radius)
        return 3.14159 * radius * radius
    case Rectangle(width, height)
        return width * height
    case Point
        return 0
    end
end

value people: list of Person is [
    { name: "ada", age: 36 },
    { name: "grace", age: 45 },
    { name: "linus", age: 17 },
]

value adults is people
    |> filter((person: Person) => person.age is at least 18)
    |> map((person: Person) => "{person.name}: {person.age}")

print(adults)
print(area(Rectangle(3, 4)))

# Optional values use T? and are narrowed with `is nothing`.
define findAge(name: text) returns number?
    for each person in people
        when person.name is equal to name
            return person.age
        end
    end
    return nothing
end

value adaAge is findAge("ada")
when adaAge is number
    print("ada is {adaAge}")
end

value totalAge is sum(map(people, (person: Person) => person.age))
print("total age: {totalAge}")

The type system

Every program is checked before it runs:

  • Inference and annotations. Bindings and function signatures are checked,

    • not assumed. Return types are part of the contract.

  • Generics and constraints. define first<T>(values: list of T) returns T?

    • works with explicit or inferred type arguments, including constraints.

  • Structural records and variants. Records are width-subtyped; variants are

    • exhaustive in match.

  • Unions, intersections and narrowing. number or text, T?, is type

    • tests, literal types, tuple types, readonly fields, mapped/conditional types, indexed access, overloads and type predicates are enforced.

  • nothing safety. Optional values must be narrowed before use; as is an

    • explicit, unchecked boundary cast.

Types are erased at runtime. The checker is the enforcer; the emitted module is plain JavaScript with no type library.

Using npm packages

Imports of npm packages, Node built-ins, React and browser globals work because the output is a plain ES module. Un-typed JavaScript boundaries are any deliberately:

#syntax 2.1

import express from "express"
import { print } from "std/io"

declare const process: any

set app to express()
app.use(express.json())

app.get("/health", (request: any, response: any) => do
    response.json({ status: "ok" })
end)

set port to 4501
app.listen(port, () => do
    print("listening on {port}")
end)

render and element blocks lower to createElement calls resolved from the module scope, so a component written in PlainScript is a normal React component — no plugin, no JSX runtime, no custom bundler:

#syntax 2.1

import { createElement, useState } from "react"

export define Counter() returns any
    set (count, setCount) to useState(0)

    render
        element "button" with onClick: () => setCount(count + 1)
            "Count: {count}"
        end
    end
end

Limitations

Known and deliberate for 2.1.0:

  • One backend. JavaScript/ESM only. The IR and emitter are separated so

    • another target is possible, but none exists.

  • No bundler. build emits one module per file. Browser projects use Vite,

    • Next or another bundler, as the integrations do. Importing the standard library in a browser needs --std-base.

  • Advanced type limits. Arbitrary intersections of unions/functions,

    • optional tuple elements and general TypeScript-style conditional inference remain absent. Readonly is a compile-time assignment check. Deferred constructs stay permissive until instantiated.

  • Concurrency is cooperative. std/task provides groups, cancellation,

    • timeouts, channels and worker handles; it cannot stop promises or host calls that ignore cancellation.

  • render blocks are not JSX. Attributes are with name: value, children

    • are statements, and dynamic lists are built with element expressions. No fragments or automatic key inference.

  • Types are erased. No runtime reflection beyond is checks on primitives,

    • lists, maps and variant tags. as is unchecked at runtime.

  • No exceptions typing. catch binds any; typed operational errors use

    • OperationResult/OperationFailure.

  • Database support requires an installed driver. std/db is SQLite via

    • Node's node:sqlite; PostgreSQL/MySQL adapters dynamically load application-installed drivers. No live PostgreSQL/MySQL server is available here, so those adapter tests use driver-shaped fakes.

  • Debugging is adapter-based. plainscript dap maps breakpoints and stack

    • frames through source maps; the VS Code integration is test-level.

  • TypeScript interop is a subset. plainscript interop translates

    • declarations with a direct PlainScript equivalent and reports the rest.

  • Benchmarks are PlainScript-only. No cross-language speed claim is made.
  • Not published yet. The npm registry serves 2.0.0; publishing 2.1.0 is a

    • separate, explicit release step.
