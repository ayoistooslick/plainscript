PlainScript 2.0

PlainScript is an independent, statically typed programming language for the JavaScript platform. It is designed to be readable without hiding the machine: every program is type-checked before it runs, lowered through an explicit intermediate representation, and emitted as ordinary ES modules that interoperate with the JavaScript ecosystem.

Version 2.0 is a ground-up rebuild of the language, compiler, runtime interface and standard library. It is a breaking release; see CHANGELOG.md and docs/MIGRATION.md.

Created by Ayodele Ayokunle David. PlainScript is MIT licensed.

What PlainScript is

  • A language with its own semantics. Blocks close with end. There is exactly one

    • spelling for each concept: let/const, function, if/else, match/case, for … in, type, import/export. There are no synonyms such as done/end or show/print/log.

  • Statically typed, with inference. Function signatures are checked, not assumed.

    • Generics, unions, narrowing, structural records, variants, exhaustiveness and nothing safety are enforced by the compiler.

  • A real compiler. Lexer → parser → type checker → typed HIR → JavaScript emitter with

    • source maps. Types are erased at runtime, so the checker is the enforcer, and JavaScript boundaries are typed any deliberately rather than accidentally.

  • Interoperable first. React, Next.js, Vite, Node, npm packages, browser APIs and the

    • Web Request/Response model are supported by emitting plain modules, not by wrapping frameworks.

  • Small and honest. The standard library covers fundamentals (text, list, map,

    • math, json, time, fs, http, io, dom, test) plus structured concurrency (std/task), WebSockets (std/ws), SQLite persistence and migrations (std/db), password/token authentication (std/auth) and runtime/schema contracts (std/contract). Service SDKs remain ordinary npm packages, not keywords.

  • Schema-derived full-stack contracts. std/contract.object derives record types from

    • runtime schemas. fallibleOperation carries a typed error union, implementFallible validates both outcomes, router dispatches by operation name, and std/db derives table columns and versioned migrations from the same schema. See Unified Contracts and the runnable SQLite + React contracts demo.

  • Editor support built in. plainscript lsp speaks LSP over stdio with diagnostics,

    • completion, hover, definitions, workspace references, rename and formatting. The VS Code extension in editors/vscode launches it.

What PlainScript is not

  • Not JavaScript with renamed keywords. The syntax, type system, module graph, pattern

    • matching and diagnostics are implemented in this repository.

  • Not a framework generator or a catalogue of service integrations; its bundled templates are

    • complete PlainScript application slices intended to stress the language and its interop.

  • Not a TypeScript superset. It compiles to JavaScript, not to TypeScript.

Quick start

PlainScript needs Node.js 20 or newer and has no runtime dependencies. From a clone:

node src/cli.js run hello.pln
# hello.pln
import { print } from "std/io"

function greet(name: text) -> text
    return "Hello, {name}!"
end

print(greet("world"))
$ node src/cli.js run hello.pln
Hello, world!

Check types without running, emit ES modules, or open a project:

node src/cli.js check hello.pln      # type-check, print diagnostics
node src/cli.js build                # compile src/**.pln into dist/
node src/cli.js new my-app           # scaffold package.json + src/main.pln
node src/cli.js new my-project --template project-management
node src/cli.js new my-store --template ecommerce
node src/cli.js new my-chat --template realtime-chat
node src/cli.js run                  # compile and run src/main.pln

Once installed as a package, the same commands are available as plainscript.

A short tour

import { print } from "std/io"
import { map, filter, sum } from "std/list"
import { upper } from "std/text"

# Records are structural types.
type Person
    name: text
    age: number
end

# Variants are discriminated unions; unit variants are plain strings.
type Shape = Circle(radius: number) or Rectangle(width: number, height: number) or Point

function area(shape: Shape) -> number
    match shape
        case Circle(radius)
            return 3.14159 * radius * radius
        case Rectangle(width, height)
            return width * height
        case Point
            return 0
    end
end

let people: list of Person = [
    { name: "ada", age: 36 },
    { name: "grace", age: 45 },
]

let adults = people
    |> filter((person: Person) => person.age >= 18)
    |> map((person: Person) => upper(person.name))

print(adults)                       # ["ADA", "GRACE"]
print(area(Rectangle(3, 4)))        # 12

# Optional values use T? and are narrowed with `is nothing`.
function findAge(name: text) -> number?
    for person in people
        if person.name == name
            return person.age
        end
    end
    return nothing
end

if findAge("ada") is number
    print("found")
end

See docs/SPEC.md for the complete language definition and docs/SYNTAX_DESIGN.md for the syntax rationale and migration notes. Run node src/cli.js ir file.pln to see the typed intermediate representation the backend consumes.

Tooling

CommandPurpose
plainscript run [file]Compile and execute a program (default src/main.pln).
plainscript build [files…]Type-check the module graph and emit .js + .js.map into dist/. With --declarations, also write <name>.d.pln so another PlainScript project can compile against the built library without its sources. Unchanged outputs are not rewritten.
plainscript watch [files…]Rebuild after .pln changes, reusing the module cache for unaffected files.
plainscript check [files…]Type-check only; exits non-zero on diagnostics.
plainscript lspStart the language server over stdio.
plainscript fmt [files…]Normalise indentation and block layout without changing tokens.
plainscript test [files…]Run std/test files and report pass/fail.
plainscript new <dir>Scaffold a project.
plainscript ir <file>Print the typed HIR that code generation consumes.
plainscript versionPrint the compiler version.

Details, including --check, --std-base and project configuration, are in docs/CLI.md.

JavaScript ecosystem

The backend emits one ES module per source file. Imports of npm packages, Node built-ins, React and browser globals work because the output is plain JavaScript with no runtime library:

import { createElement, useState } from "react"
import express from "express"
import { readFile } from "node:fs/promises"

declare const document: any

render blocks lower to createElement calls resolved from the module scope, so a component written in PlainScript is a normal React component, usable in Vite, Next.js or any other React toolchain — no plugin, no JSX runtime, no custom bundler.

Limitations

These are known and deliberate for 2.0.0, not oversights:

  • One backend. JavaScript/ESM only. The IR and emitter are separated so another target

    • is possible, but none exists.

  • No bundler. build emits one module per file. Browser projects use Vite, webpack or

    • Next to bundle, as the demos do. Importing the standard library in a browser requires --std-base plus serving those module URLs (see the full-stack demo).

  • Advanced type completeness. Literal enum unions, tuples, keyof, typeof,

    • generic constraints and std/contract-derived models are implemented. Conditional and mapped types, indexed-access types, user-defined type predicates and general function overloads are not.

  • Concurrency is cooperative. std/task provides task groups, cancellation, timeouts,

    • channels and worker handles; it cannot stop JavaScript promises or host calls that ignore a cancellation signal. There is no compiler-level task syntax.

  • render blocks are not JSX. Attributes are with name: value, children are

    • statements, and dynamic child lists are built with element expressions. There are no fragments, context shorthand or automatic key inference.

  • Types are erased. No runtime reflection beyond is checks on primitives, lists,

    • maps and variant tags. as is unchecked at runtime.

  • No exceptions typing. catch binds any; typed operational errors use

    • OperationResult/OperationFailure instead.

  • Database support is SQLite-first. std/db targets Node 22's built-in node:sqlite;

    • other drivers need an adapter with the same small surface. WebSocket fragmentation and extensions are not implemented.

  • LSP scope. Rename and references follow imported PlainScript symbols across the

    • workspace, but refactoring is limited to symbol rename. There is no debug adapter yet; source maps are emitted for external debuggers.

  • Benchmarks are PlainScript-only. npm run bench is reproducible, but no pinned

    • TypeScript baseline is installed, so no cross-language speed claim is made.

  • Not published yet. npm still serves 1.1.5. Publishing 2.0.0 is a separate, explicit

    • release step.
