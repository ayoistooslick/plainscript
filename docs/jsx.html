JSX and React

PlainScript parses JSX as native syntax. A .pln file can contain React components directly: there is no separate .jsx layer, no Babel step and no runtime wrapper. The compiler parses elements and fragments, type-checks props where it can, and lowers the tree to either the classic createElement factory or the automatic JSX runtime.

JSX is available in 2.1 source, including files without an explicit pragma, because the dialect and the JSX transform are independent. Components can still use the ordinary PlainScript constructs around the markup.

A first component

The default runtime is classic: JSX becomes createElement(type, props, ...children). React projects therefore need createElement in scope, exactly as a classic-runtime JavaScript component does. Fragment is also required when the component uses <>…</>.

return any is the normal type for a React element here. React's own types are not modelled by the checker; the boundary type is any, while the component's props are fully checked at PlainScript call sites.

Fragments and children

Fragments have no wrapper element. Expression containers may contain any expression, including a call that returns an array of elements. Keys are not inferred; pass key explicitly inside a mapped list, as in JavaScript React.

Attributes

All ordinary JSX attribute forms are supported:

  • name="text" and name={expression} are equivalent to React props.
  • A bare attribute such as disabled becomes true.
  • {...record} spreads a record into the props object.
  • HTML entities in text (&amp;, &nbsp;, numeric entities) are decoded.
  • Text-only children are whitespace-normalised the way React's transform does:

    • newlines and indentation around text collapse, while meaningful spaces inside a line are kept.

  • {/ … /} comments are allowed inside a JSX tree.

Attribute names are emitted verbatim. React's className, htmlFor and onClick spellings are therefore the ones to use; PlainScript does not rename attributes.

Events and hooks

Hooks are ordinary imported functions, and event handlers are ordinary PlainScript lambdas:

The generated module is a normal ES module, so hooks, context, refs, suspense and third-party components work exactly as they do in JavaScript React. A component imported from an npm package is typed any; local components with a record prop type are checked.

The emitted module imports jsx/jsxs from react/jsx-runtime (or from <importSource>/jsx-runtime). Components, props, children and keys behave the same; only the factory changes.

For Preact or another compatible runtime:

Automatic JSX accepts class as an attribute because Preact does. React's automatic runtime expects className; the compiler does not rewrite either.

Project configuration

Per-file pragmas override project defaults. Defaults live in plainscript.config.json, either under a top-level jsx object or under compilerOptions.jsx:

Supported pragmas, read from the first lines of a file:

PragmaEffect
# @jsx hClassic factory function, for example Preact's h
# @jsxFrag FragmentFragment factory and forces the classic runtime
# @jsxRuntime automaticSelect the automatic runtime
# @jsxRuntime classicSelect the classic runtime
# @jsxImportSource preactAutomatic runtime package; also selects automatic

The precedence is: built-in default → plainscript.config.json → file pragma. JSX options are resolved per file, so a React page and a Preact island can live in one repository.

Prop checking

When a component has a declared record prop type, the checker validates its call sites:

  • PS3421 — a prop value has the wrong type.
  • PS3420 — a prop name is not declared.
  • PS3422 — a required prop is missing.
  • PS3405 — classic JSX is used without the factory in scope.

Optional props end in ?; spread props are not checked member by member because their record type may not be statically known.

React tooling

The integrations/react-vite project is a React 19 + Vite application whose component is written in PlainScript JSX. Its test renders the component through react-dom/server and its production path runs the normal Vite build; no Babel JSX plugin or separate JavaScript component is maintained.

For a Vite project:

  1. Write the component in src/App.pln with #syntax 2.1.
  2. Import React's createElement (classic) or use the automatic pragmas.
  3. Run plainscript build to emit generated/App.js.
  4. Let Vite import the generated module as usual.

Source maps are emitted beside the generated module, so browser and Node stack traces point back to the .pln source.

What is deliberately not supported

  • .tsx files are not parsed; PlainScript's own .pln files contain JSX. Use

    • plainscript migrate to wrap an existing TSX component behind a boundary, or rewrite it as PlainScript JSX.

  • TypeScript's JSX type namespace (JSX.IntrinsicElements) is not imported.

    • Only component props declared in PlainScript are checked.

  • There is no automatic key insertion, and no compiler-managed React state.
  • Vue templates and Svelte components are not JSX; only JSX factory runtimes

    • are supported. A framework that compiles JSX through a compatible factory or automatic runtime works.
