PlainScript engineering status

This file records the current verified state. Earlier per-defect logs are preserved in git history and in docs/AUDIT.md; stale status claims are not kept here.

Verified baseline

Run npm test from the repository root. The current suite covers the compiler, type checker, contracts, database migrations, authentication, concurrency, jobs, WebSockets, SSE, LSP, watch mode, CLI, declarations, packages, templates, demos and runtime behavior. The exact count is printed by the command; CI should treat any failure as a release blocker.

Additional checks:

node scripts/benchmark.js 40 7   # reproducible compiler timing
plainscript check demos/contracts-fullstack/src/shared.pln
plainscript check demos/contracts-fullstack/src/server.pln
plainscript check demos/contracts-fullstack/src/App.pln

What is complete

  • Contracts through every layer. Runtime schemas, schema-derived checker types, typed

    • success/error results, validation on both sides, authorization callbacks, operation router/HTTP transport, SQLite/PostgreSQL/MySQL table mapping, versioned migrations with rollback.

  • Authentication. scrypt password hashing, constant-time verification, HS256 bearer

    • tokens with claims validation, policies, and the demo's login/token flow.

  • Type system. Enum literal unions, fixed and variadic tuples, readonly record

    • fields, keyof, typeof, generic constraints, record intersections, concrete and deferred indexed access, conditional types (including distribution over a naked type parameter), mapped types, function overloads (including imported/declaration overloads), user-defined type predicates, recursive types and documented function/container variance.

  • Concurrency. Task groups (including nested parent groups), cancellation, timeouts,

    • channels with buffered-close delivery, worker handles, and cleanup/failure tests.

  • Jobs. Bounded-concurrency in-process queue with retries/backoff, timeouts,

    • cooperative cancellation, drain, close, event hooks, memory/SQLite stores, startup recovery, persisted attempt records and missing-handler failure reporting.

  • Tooling. LSP diagnostics/completion/hover/definition/references/rename/symbols/

    • formatting, semantic tokens, quick-fix code actions, workspace import handling, a minimal stdio DAP server backed by Node's inspector/source maps, VS Code LSP/debugger integration, watch mode, module cache invalidation and unchanged-output skipping.

  • Ecosystem. HTTP/SSE (std/http), WebSockets with fragmentation/control frames

    • (std/ws), SQLite (std/db), PostgreSQL/MySQL adapters (std/db-postgres, std/db-mysql), auth (std/auth), OIDC/SAML helpers (std/oidc, std/saml), async/tasks (std/task), jobs (std/jobs), React/Next/Vite/Node interop and eight starters.

  • Adoption. Conservative plainscript migrate reporting, plainscript interop for a

    • supported .d.ts subset, JavaScript/npm interop and incremental migration guidance.

Remaining limitations

See the README limitation list and docs/ROADMAP.md. In particular, a MongoDB std/db adapter, live PostgreSQL/MySQL test servers, arbitrary TypeScript .d.ts parsing, WebSocket extensions, distributed/leased job workers, VS Code UI automation for DAP and a cross-language performance baseline are not implemented or not verified here. PostgreSQL and MySQL adapter tests use injected driver fakes; see DATABASES. No package has been published as part of this work.
