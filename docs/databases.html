Databases

PlainScript has no database runtime of its own. Application code imports an ordinary npm driver, passes values as bound parameters, and keeps contract validation at the boundary. The bundled SQLite, PostgreSQL and MySQL adapters provide schema-derived tables and migrations without making a driver a compiler dependency.

Supported surfaces

SurfaceDriverTable/migration API
std/dbNode 22 node:sqliteSynchronous table() and migrate()
std/db-postgresApplication-installed pgAsynchronous table() and migrate() via the same std/db helpers
std/db-mysqlApplication-installed mysql2/promiseAsynchronous table() and migrate() via the same std/db helpers
MongoDBApplication-installed mongodbDirect driver interop; no adapter

The compiler and bundled runtime still have zero npm dependencies. Install pg or mysql2 in the application that uses the adapter. The adapter loads it dynamically and raises DatabaseError with an installation hint when it is missing.

SQLite

table derives columns from the same schema used by std/contract, validates every row through that schema and binds every value. migrate records versions in plainscript_migrations, uses BEGIN IMMEDIATE, rolls back a failed migration and refuses duplicate versions or history gaps. rollback requires a down function.

Node's node:sqlite is marked experimental by Node 22. The checked-in tests cover it; a production service should verify the exact Node version it deploys.

PostgreSQL

open() creates one dedicated pg.Client; use openPool() for request-serving applications. openPool().transaction(work) checks out one client, runs BEGIN/COMMIT (or ROLLBACK) on that session and releases it. The adapter translates ? placeholders outside quoted strings/comments to $1, $2, … so the SQL generated by std/db.table works unchanged. Generated auto-increment columns use BIGSERIAL, and inserts that omit the key use RETURNING to read it.

Connection options are passed through options.client to pg; a connection string may be supplied to open/openPool directly. Close the database during shutdown.

MySQL and MariaDB

The adapter parses mysql:// and mariadb:// URLs into host, port, user, password, database and query-string options, then lets explicit options.client values win. Writes use mysql2.execute; reads use query. Generated auto-increment columns use BIGINT AUTO_INCREMENT, booleans use TINYINT(1), and arrays/objects use native JSON columns. table().insert() reads insertId and fetches the inserted row. Transactions use the driver's beginTransaction/commit/rollback on a checked-out connection.

MongoDB

MongoDB is document-oriented, so it stays direct driver interop rather than pretending to implement the SQL table API:

MongoDB has no SQL parameterization; validate and shape documents through std/contract before writing, and never interpolate untrusted text into a query object. Driver methods are any at the boundary, so declare thin typed wrappers for your own API.

Validation and serialization

Validate at the trust boundary with the same schema the contract uses:

std/contract strips unknown keys for object schemas, rejects them with unknownKeys: "strict", and parses nested arrays/objects. Store only validated values. SQLite stores structured values as text and std/db.table encodes/decodes them; the PostgreSQL and MySQL adapters use native JSON transfer. Always use bound parameters; do not build SQL by interpolating request values.

Connection lifecycle

  • Create one pool/client at process startup; do not open a connection per request.
  • Release clients in finally; roll back before releasing.
  • Set pool limits and connect/statement timeouts for the deployment.
  • Close the pool on SIGTERM after draining HTTP and jobs.
  • Use TLS and a least-privilege database user in production; keep credentials in the

    • deployment's secret store, never in .pln source.

Verified scope

tests/db.test.js verifies SQLite tables, persistence, parameter binding, migrations, rollback and failure behavior. tests/db-adapters.test.js verifies PostgreSQL and MySQL placeholder translation (including quoted, commented, doubled-quote and dollar-quoted inputs), SQL/type generation, query binding, transaction statements, connection lifecycle, URI parsing and the asynchronous declaration surface using driver-shaped fakes. tests/db-live.test.js is the real-server harness. It skips unless both the URL and the driver are present:

The harness creates and drops its own table, then checks connection failure, parameterised insert/select, injection-shaped values, invalid-query errors, rollback and commit. No live PostgreSQL or MySQL server is available in this repository's test environment (no database service, Docker daemon or root access), so those adapters are not claimed as server-integration tested here. Install the driver in the application's own package.json and run this harness (or your own suite) against a real instance before deployment.

SQLite table methods are synchronous. The PostgreSQL and MySQL adapters return Promises for table() operations and must be awaited; the type declarations select AsyncTable for an AsyncDatabase. Migrations are asynchronous in both cases because migrate() always returns a Promise.
