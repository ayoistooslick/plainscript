Application templates

PlainScript ships eight starters. They are real program slices, not static landing pages: each has PlainScript source, package metadata and documentation. The three application templates include persistent storage; the framework starters show the supported boundary.

TemplateCommandWhat it contains
project-managementplainscript new my-project --template project-managementSQLite-backed projects, tasks, status updates, dashboard statistics and browser client.
ecommerceplainscript new my-store --template ecommerceSQLite catalogue, inventory-safe simulated checkout, orders and browser client.
realtime-chatplainscript new my-chat --template realtime-chatSQLite conversations/messages with live Server-Sent Events and a browser client.
react-viteplainscript new my-ui --template react-viteReact component written in PlainScript, compiled to src/generated, bundled by Vite.
nextplainscript new my-site --template nextNext.js App Router page rendered by a PlainScript React Server Component.
expressplainscript new my-api --template expressExpress-compatible REST API using the real express package and typed handlers.
cliplainscript new my-cli --template cliCommand-line starter using std/io.args, print and optional arguments.
libraryplainscript new my-lib --template libraryTyped exported records/functions and plainscript build --declarations.

All templates expose npm run check. The three application templates and the library also provide npm run build; framework templates compile PlainScript before their framework's build/dev command. Configure DB_PATH and PORT for database templates, and AUTH_SECRET for the contracts/authentication demonstration, before npm start.

The .pln sources are the implementation; emitted JavaScript is generated output. Every scaffold is exercised by tests/cli.test.js with plainscript check, so a template cannot silently drift into invalid source. Framework builds (vite build, next build) require installing each starter's declared dependencies; those full builds are not run by the compiler's zero-dependency test suite.

Known follow-up work is documented in each template README rather than hidden behind a claim of completeness.
